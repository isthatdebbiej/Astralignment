## Product promise and falsifiable claim

Turn a human-confirmed stage model into a reproducible robot-coordination experiment. Two individually competent learned locomotion policies can satisfy their destination objectives while violating a shared contact or human-access constraint. Astralignment makes that failure visible, gives Astra an executable repair interface, and tests the resulting source under unchanged evaluation rules.

The defensible claim is **failure discovery and measured coordination repair in this simulator**, not general alignment, intent detection, formal verification, sim-to-real certification, or a newly trained locomotion model. Better future models might solve the baseline unaided; stale perception, incompatible local objectives, uncertain physical models and evaluation integrity remain useful testing targets. The independent baseline is not presented as Astra behaving badly.

## Demo interaction and architecture

1. A human pairs an iPhone, explicitly starts video, fixes its camera, and measures the stage. Four image/floor correspondences establish a planar homography in meters.
2. A human marks obstacle ground corners and confirms height. Optional Astra still-image observations suggest corners only; they cannot apply geometry. The same-ID edit supports a moved prop.
3. Confirmed geometry creates a new scene epoch. Obstacle edits use atomic expected-epoch and episode-UUID checks; stale updates and stale checkpoints fail. Episode UUIDs also prevent a restarted simulator's epoch counter from making old evidence appear fresh. The scene is a proxy, with explicit friction/contact and clearance assumptions.
4. Two G1 humanoids walk using pinned pretrained Unitree policies. The simulator has one 500 Hz clock, two separate 50 Hz recurrent policy states, real PD torques, gravity and contacts. The renderer consumes body poses; it cannot move robots.
5. A bounded seeded search evaluates the independent baseline. Failure includes contact, fall, human-zone or boundary entry, and failure to complete both goals. Contact metrics count **physics timesteps**, not separate incidents. A fixed 0.45 m XY clearance envelope is a modeling assumption, not certified human safety.
6. Freeze full MuJoCo integration state, both LSTM hidden/cell buffers, actions, phase, controller state and RNG. A state hash identifies the captured checkpoint. Branch execution does not mutate the live world.
7. Astra uses `inspect_failure`, `test_controller`, and `submit_controller`. It writes `function coordinate(input)` as executable JavaScript. No real-time motor commands are generated by the language model.
8. Every 0.2 simulated seconds the generated source runs in a separate QuickJS/WASM worker. Its only input/output is bounded JSON; explicit returned memory preserves state between calls. It receives no host functions, network, filesystem, module loader or API key. CPU, source/output size, memory, command speed and world bounds are limited independently.
9. Fixed Python evaluation reads physical outcomes, not the coordinator's claimed success. Frozen-source replay and held-out seeded tests publish failures too. Held-out results carry their own scene layout so displayed goals match the evaluated trajectory. A passing single episode is not generalization evidence.

| Boundary | Interface | User-visible reason |
| --- | --- | --- |
| Phone ↔ viewer | WebRTC; expiring origin-bound pairing; optional TURN | Continuous real video without uploading every frame to an LLM |
| Viewer ↔ gateway | Same-origin authenticated HTTP and WebSocket | One operator workspace, source/evidence updates, browser-safe deployment |
| Gateway ↔ simulator | Loopback HTTP, bounded commands, epoch guards | Expensive reasoning cannot stall or bypass the low-level controller |
| Generated code ↔ host | QuickJS/WASM worker, JSON only | A buggy repair cannot edit its evaluator or read credentials |
| MuJoCo ↔ Three.js | Original mesh-local transforms + body world poses, WXYZ→XYZW conversion | Actual robot articulation and shared collision state remain visible |
| Optional DimOS ↔ simulator | Typed native streams, observed pose and expiring XY commands | Adapter toward robot middleware; native Ubuntu operation must be separately verified |

## Engineering choices with direct demo impact

- **Pinned walking policy instead of training:** immediately testable G1 model/controller compatibility and genuine dynamic walking. Source, license and hashes are preserved.
- **One coupled world instead of two independent simulations:** robot–robot contacts and right-of-way failures actually exist.
- **Same checkpoint, not just the same seed:** recurrent memory and contact/integration state can otherwise change a comparison even when its label looks identical.
- **Pure explicit coordinator memory:** fork/replay state is inspectable and bounded; hidden host globals cannot leak across branches.
- **Immutable source and evaluator boundaries:** tests cannot be passed by rewriting the score. The authored reservation reference stays labeled as reference.
- **Event-driven model use:** no tokens at physics frequency. Low effort is appropriate for selected-image observation/access checks; high effort is used for executable coordination repair.
- **Shared STL loading per viewer:** the two robots reuse geometry instead of downloading duplicate meshes. Visual and collision provenance remains explicit. The original 25 MB mesh set is not falsely described as optimized for all mobile devices.
- **Compact event snapshots and bounded frame buffers:** status updates don't repeatedly send complete replay arrays. Full results are fetched separately.
- **Durable budget reservation before dispatch:** a gateway crash cannot erase an in-flight cost allowance. Reported token costs are estimates, not a billing statement.
- **HTTP/WebSocket plus focused Playwright QA:** browser input, live pose rendering and media transport are testable. CDP is unnecessary for the core simulator; it does not make LLM inference into a high-frequency controller.

## Research vs. application

The implementation reuses Unitree's released model, checkpoint and deployment equations; it is not a reproduction of a new locomotion paper. The repair loop is an applied, bounded counterexample-guided workflow rather than a formal proof or novel alignment theorem. The useful research artifact would be a reproducible collection of human–robot coordination counterexamples, frozen states, repair sources, held-out outcomes and failure analyses. A six-hour demonstration alone does not establish scientific novelty.

## Current exclusions

No 3DHM, arbitrary video-to-metric-physics reconstruction, dexterous manipulation, trained human dynamics model, raw LLM torque control, automatic cloud/GPU purchase, Kubernetes, vector database, or fleet beyond two humanoids. No native DimOS or iPhone claim without its actual runtime/device test. See `VERIFICATION.md` for what ran, and the original-asset attribution for upstream sources.
